Spec Kit in detail: GitHub's open-source SDD toolkit

Constitution
Project rules every spec inherits

Specify
What to build and why

Clarify
Agent asks about gaps

Plan
Technical design and stack

Tasks
Ordered work items

Implement
Agent writes the code

What it is

  • Released by GitHub in September 2025, MIT licence, free
  • A CLI that installs templates and slash commands into the repository
  • Works with 30+ coding agents; no lock-in to one vendor
  • Most adopted SDD framework; best for greenfield work

Where it falls short

  • Specs do not update during implementation, so they drift from the code
  • Clarify and analyse steps are advisory; nothing gates the build
  • No check that the running code does what the spec says
  • Heavy ceremony for small changes and existing codebases

As of mid-2026. Sources: github.com/github/spec-kit, codemyspec.com, braingrid.ai, webreactiva.com. GitHub itself calls Spec Kit an experiment.

Link to the main argument: Spec Kit structures the workflow well, but spec, plan and context are still written up front and the human returns at review. That is the harness-without-method pattern the article criticises. Adoption figures differ by source (roughly 90k to 115k GitHub stars in the first half of 2026).
