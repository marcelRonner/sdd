What a complete Spec Kit spec contains

spec.md: the chapters of the feature specification

ChapterContent
1. User scenarios and testing (mandatory)Prioritised user stories (P1 to P3), each with an independent test and Given/When/Then acceptance scenarios
2. Edge casesBoundary conditions and error scenarios
3. Functional requirements (mandatory)Numbered requirements (FR-001 ...); unclear points flagged for clarification
4. Key entities (if data is involved)Data objects, their meaning and relationships
5. Success criteria (mandatory)Measurable, technology-agnostic outcomes (SC-001 ...)
6. AssumptionsDefaults, scope boundaries, dependencies on existing systems

contracts/Interface definitions

Source: spec-template.md and plan-template.md in github.com/github/spec-kit (main branch, October 2026).

The spec itself deliberately holds the what and why; the how sits in plan.md and its companion files. Still, one feature produces up to eight documents written before any code exists, which is the upfront burden the article questions. Chapters 1, 3 and 5 map loosely to the article's intent and expectations; plan.md and the rest map to context. The one-line descriptions of research.md, data-model.md, contracts and quickstart.md are summaries, not template wording.
