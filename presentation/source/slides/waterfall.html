The spec becomes the system

A spec precise enough to generate a system is as complex as the system. A vague one makes the agent guess, and drift starts early.

Regenerating is rewriting

The same spec yields different systems. Fixes made since the last run are lost, so teams edit code and the spec quietly goes stale.

Document churning

Agents produce plan after plan that reads well but was never tested against reality. Only running code has to match reality.

Where agents do pay off: instant knowledge (APIs, legacy code) and cheap spikes that can be thrown away.

Source: U. Barbini, "Spec-Driven Development: The New Waterfall", Medium, August 2026.

Barbini concedes the tools are new and powerful, and that some SDD work is honest practice. His objection to regeneration rests on today's non-determinism and cost, which he expects to fall. He also promotes his own book, Process Over Magic. His "holodeck" image: an agent will specify something impossible without noticing, and heavily mocked tests can be green while connected to nothing.
